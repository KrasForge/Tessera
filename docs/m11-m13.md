# M11 / M13: multicore temporal workstation

## Scope

The common kernel implementation now combines admitted multicore DSP execution,
managed graph replacement, the serial control shell, and versioned session
persistence. `arch/arm64/main.c` remains the physical-board bring-up image;
`run-arm-workstation` boots the integrated QEMU application. Physical CM4 audio,
I2S/DMA and SD-controller acceptance remain M10 work. A QEMU pass is not a
hardware worst-case execution-time or end-to-end audio measurement.

## Run the workstation

```sh
make run-arm-workstation CROSS_COMPILE=aarch64-linux-gnu-
```

The frontend sends commands through the emulated PL011. Its `:quit` and
`:reboot` commands pause safely and export the RAM-backed FAT16 block image
before terminating QEMU. `:reboot` starts a **new emulator process** and imports
that image, with a fresh kernel, process table, worker state and audio buffers.
The default image is `build/workstation-card.img`; the frontend refuses to
silently overwrite an existing image with an incompatible size. Kernel `quit`
is also intercepted by this frontend to flush storage. An abrupt host kill or
power loss does not flush this RAM-backed device.

For a different image, after building:

```sh
python3 scripts/run_workstation.py --image build/my-card.img
```

The QEMU console profile reserves CPU0 for cadence/output and CPU3 for shell,
loading, FAT operations and reclamation. CPU1 and CPU2 run DSP. `cores 3` is
rejected in that profile, rather than scheduling DSP onto the blocking console
core. The headless M11 profile uses all three DSP workers, CPU1–3. A board host
may select its own supported mask; CPU0 is never an admissible DSP target.

## Example session

These paths are seeded as actual ELF files on the emulated FAT16 volume:

```text
tessera> load /sd/SYNTH.ELF
loaded pid 1
tessera> load /sd/FILTER.ELF
loaded pid 2
tessera> wire 1 2
tessera> wire 2 dac
tessera> contract 1 hard 400us deadline=1000us policy=mute
tessera> contract 2 hard 400us deadline=1200us policy=mute
tessera> pin 1 2
tessera> pin 2 1
tessera> start
tessera> ls
tessera> stats
tessera> patch save /sd/LIVE.TSP
tessera> :reboot
tessera> patch ls
tessera> patch load /sd/LIVE.TSP
tessera> start
```

PIDs are reported by `load`; use the actual values rather than assuming they
restart at one within an existing kernel session. `ls` lists paths, assignment,
criticality, periods, deadlines, budgets, policies and graph wiring. `stats`
reads bounded, atomic per-PID snapshots and reports admitted/completed work,
budget offences, deadline misses, shedding, kills and service times.

`set-param <pid> <id> <value>` accepts signed integers, decimals with at most
nine fractional digits, or exact IEEE-754 binary32 bits such as `0x3f000000`.
The shared parser rounds decimal rationals to binary32 without kernel FP
instructions. Invalid numbers, overflow, duplicate contract options, excessive
arguments and overlong command lines are rejected before mutation. A line is
never executed as a silently truncated prefix. Backspace, help and echo remain
available. `wait` and `inspect` in the QEMU application are observation commands,
not requirements of the common shell API.

Additional contract examples:

```text
tessera> contract 3 soft 100us period=2blocks deadline=1000us policy=bypass
tessera> contract 4 best 200us policy=degrade skip=2
tessera> contract 5 soft 150us policy=strikes kill=3
tessera> pin 3 auto
tessera> cores 2
```

The exact accepted policy spellings are listed in the shell implementation;
`degrade` reduces execution rate by skipping future releases, not automatic
DSP quality tuning. Same-frame rates and dependencies must satisfy the M12
frame-synchronous model. The common API works in generic-counter **ticks**;
shell `us`, `ms`, `ticks` and `blocks` are converted with overflow checks.

## Multicore admission and execution

`temporal_multicore` reuses M12 structural contract validation and ordering,
then assigns each dependency-ready job to the earliest-finishing permitted
core, or its explicit pin. The priority is HARD, SOFT, BEST_EFFORT, then earliest
deadline within class, with PID as a stable tie-breaker. Admission reserves
plugin execution plus two bounded `job_overhead` allowances (input preparation
and output publication) and the declared cross-core handoff cost. A reverse
pass propagates latest finishes through both graph dependencies and each
core's chosen sequence, so an earlier job cannot consume a successor's slot.
This is a conservative sufficient test, not an optimal bin-packing solver.

The worker wake path completes publication stores before signalling SEV.
A consumer waits only until its latest safe start and requires a release/acquire
publication tagged with the **current frame**. Missing dependencies produce
silence and a deadline/dependency miss, not a false CPU-budget offence or use
of stale samples. CPU0 never waits for a worker: if a previous frame is still
in flight, it skips the whole new frame, attributes late cores and preserves
all in-flight sample storage. Skipped work is not queued for catch-up.

The M12 timer/policy executor still owns actual EL0 preemption and overload
handling. Parameter events use a host-only SPSC queue; the owning worker
executes them within the **same outer block budget** as its DSP callback.
Untrusted plugins cannot alter queue indices or authorize their own control
calls. The inherited lifecycle call budgets contain initialization, handshake,
parameter and destructor failures.

## Graph replacement without deliberately dropping a frame

The control CPU constructs an inactive graph and admits it while the old graph
continues running. Plugin instances, trusted double-buffered outputs and
per-PID scheduler state have stable addresses. New instances are fully loaded
and initialized before publication. At a drained frame boundary CPU0 collects
the old complete output, publishes the prepared configuration, and kicks the
new frame. It does not load, allocate, destroy plugins, copy whole scheduler
arrays or wait for the control writer.

Retired instances are reclaimed by the control CPU only after acknowledgement.
Rejected wiring, placement, budgets, incompatible timebases and failed partial
loads leave the old active configuration intact. A request timing out before
claim is cancelled. A swap already claimed by CPU0 is never freed underneath
it; `SESSION_EINPROGRESS` reports indeterminate completion until acknowledgement.
A manual `pause` deliberately supplies silence and a later start establishes a
new release epoch. Hot edits instead preserve the epoch, offence history and
feedback history of surviving PIDs.

This guarantees the ownership/publication protocol, not mathematical signal
continuity for arbitrary user edits. Removing the only DAC source produces
intentional silence; a sudden gain or topology change can produce a click.
Hardware timing bounds still need measured dispatch, memory/cache and timer
allowances. Explicit feedback is one previous accepted frame; after a skipped
frame, previous-frame feedback is invalidated rather than replayed blindly.

## Session persistence and transport

`# tessera-session v1` stores source paths, complete contracts, core count,
pins, parameter bits, wiring and feedback flags, plus sample rate, block size
and counter frequency. It is separate from the older patch v1 format. The
loader validates the complete replacement before publication and rejects a
mismatched timing domain rather than silently reinterpreting saved ticks.
Save writes a temporary file then renames it. This is not a journaled,
power-loss-atomic filesystem guarantee.

The M13 acceptance test exports and imports the full block image using QMP.
It does not emulate an SD controller or claim physical card testing. The
common VFS/FAT interface can use a board-supplied `fat_fs_t` read/write backend.
Sample transport uses trusted per-plugin input/scratch mappings and published
kernel-only buffers. A single input preserves exact float bits. Multiple
inputs mix in saturated Q1.31; NaN/Inf convert to silence at conversion
boundaries. DAC output is interleaved PCM16 in this application.

## Gates and timing modes

```sh
make test-arm-m11-m13 CROSS_COMPILE=aarch64-linux-gnu-
make test-arm-session-tsan
make test-arm-m12-complete CROSS_COMPILE=aarch64-linux-gnu-
```

The new QEMU functional gates explicitly use instruction-counted TCG at
`shift=0` (one nanosecond per emulated instruction), not a calibrated Cortex-A72
execution model. M12's older timing fixture retains its own declared shift.
Portable threaded tests, including 1,200 live swaps under ThreadSanitizer,
provide separate real-host concurrency coverage. A passing instruction-count
run does not replace hardware timing evidence.

Strict wall-clock diagnostic modes remain available, without changing guest
budgets, sample counts or zero-miss assertions:

```sh
make test-arm-session-qemu SESSION_QEMU_FLAGS='-accel tcg,thread=multi' CROSS_COMPILE=aarch64-linux-gnu-
make test-arm-session-console SESSION_CONSOLE_MODE=wallclock CROSS_COMPILE=aarch64-linux-gnu-
```

Both host-scheduled runs and slower instruction-count models produced misses
during development. Those logs are retained, not relabelled as success. See
`m11-m13-verification.md` for the exact tested source and results.
